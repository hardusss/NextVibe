# nv — NextVibe push & email console

`python manage.py nv` opens a full-screen menu (arrow keys + Enter, Ctrl-C = back to menu): audience overview, find a user, send to one user, send to a segment (campaign wizard with A/B variants, deterministic samples, test-to-yourself, dry run, typed confirmation above 50 recipients), campaign status, Expo push receipts, push-token validation, email setup check (Resend), templates.

State lives in `nvcli/logs/` (gitignored): one `<campaign>.jsonl` per campaign (one line per delivery, `(user_id, channel)` already `sent` is never re-sent; a dry run logs `status: "dry"`), `_index.json`, `optout.json` (written by the public unsubscribe links and by bounce/complaint webhooks), `_events.jsonl` (Resend webhook events), `errors.log` (tracebacks never reach the screen).

Templates are YAML in `nvcli/templates/`. Push and short emails use `name`, `channel`, `title`, `body`, `deeplink`, `data`, `cta_label`; a short email is wrapped in `templates/email/base.html`. A full email (`seeker-badge-email`) carries `subject`, optional `subject_b` (A/B on the subject line alone: the wizard offers "Same email, subject B"), `preheader`, `link`, `from`, `reply_to`, a `text` part and an `html` part (inline CSS, sent as-is); both parts must contain `{unsubscribe}`. Placeholders `{username} {first_name} {rep} {joined} {events} {met} {seeker} {seeker_total} {unsubscribe}` resolve per user, `{link}` and `{preheader}` are the template's own values, anything else is asked for in the wizard, and an unresolved placeholder blocks the send. Values are HTML-escaped in the `html` part. Templates → Render for a user saves the exact HTML to `logs/preview-<name>.html`.

Push: Expo in batches of 100 with 2 s pauses and 3 retries on 429/5xx (`EXPO_ACCESS_TOKEN` optional); push `data` carries `{campaign, variant, wave}` so the app can report `campaign_open` to Vexo. A deep link on `https://nextvibe.io/u/…` goes out as the in-app path (`data.url`, e.g. `/u/meets`), since the app has those screens; emails keep the web link.

Proof of Meet backlog: after `manage.py backfill_meet_slugs`, send template `meet-cards-ready` once to segment `meet-card` (people with at least one meet card). Its link `https://nextvibe.io/u/meets` opens POAPs & History in the app. Send it only after the app update that knows `/u/meets` is live: older versions open that path as a profile.

Email: Resend's HTTPS API only; the server can't reach SMTP. `RESEND_API_KEY`, sender `DEFAULT_FROM_EMAIL` (or the template's `from`). Campaigns use the batch endpoint (≤100 per call, 0.6 s apart, permissive validation so a rejected address fails only its own line, 429 retried 3× 2 s apart, a bad key / unverified domain / quota stops the run); one-off and test sends are single calls with an `Idempotency-Key`. Each message has `List-Unsubscribe` + `List-Unsubscribe-Post` (one-click), `X-Entity-Ref-ID`, and `campaign` / `variant` / `wave` tags; Resend's email id is logged as `ticket`. Users without a valid email, opted out, inactive or banned are skipped. Before any real send the console checks the key and that the sender domain is verified in Resend (a red panel lists the DNS records otherwise). Django's own `send_mail` goes through `nvcli/email_backend.py` (`EMAIL_BACKEND`).

Unsubscribe: `GET`/`POST /u/e/<token>` on the API host (`POST` is RFC 8058 one-click, no CSRF), `GET /u/p/<token>` for push. Not on nextvibe.io: the app claims those paths (iOS `*`, Android `/u/*`, and `/u/e` is the tap link), so a link there opens the app.

Opens and deliveries: register `https://api.nextvibe.io/api/v1/nv/resend-webhook/` in Resend → Webhooks (events `email.delivered`, `email.opened`, `email.clicked`, `email.bounced`, `email.complained`) and put its signing secret in `RESEND_WEBHOOK_SECRET`. Calls are checked against the Svix signature (400 otherwise) and appended to `_events.jsonl`; a permanent bounce or a complaint adds the recipient to `optout.json`. Campaign status joins the events on `ticket` and shows delivered / opened / clicked / bounced / complained per variant. Opens need open tracking on for the domain in Resend.

Only DB writes: clearing `expo_push_token` when Expo says `DeviceNotRegistered`. Tests: `manage.py test nvcli`. Wording guard: templates must not contain reward / earn / SKR / farm / "points for".
